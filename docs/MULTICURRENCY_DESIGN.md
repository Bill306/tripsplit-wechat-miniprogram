# 多币种与汇率设计

日期：2026-10-04。依据：用户确认“自动参考汇率 + 手动修改 + 实际扣款金额覆盖”。

## 体验

- 新行程选择结算币种，默认人民币；创建后保持固定，避免重算旧账。
- 记账选择原币种、填写原币金额。不同币种提供自动参考、手动汇率、实际扣款三种方式。
- 自动参考按消费日期查询 Frankfurter，显示来源和实际汇率日期；非交易日使用此前可用报价，不伪装为当日实时价。
- 汇率不可用时保留表单，允许显式改为手动或实际扣款，禁止静默使用 1:1 或其他来源。
- 账单保存原金额、原币种、结算币种、换算方式、汇率快照、来源及日期。编辑备注不刷新旧汇率；修改币种/日期后必须重新选择报价。
- 列表、详情、成员统计和结算使用明确币种标识。详情同时展示原币和换算金额。

## 数据与正确性

- 首批支持 CNY、HKD、USD、EUR、JPY、GBP、AUD、CAD、SGD、THB、KRW、CHF。
- JPY/KRW 按零位小数，其余币种按两位小数处理；所有记账与分摊金额使用整数最小货币单位。
- 为兼容已有数据，`amountFen` 字段仍保留名称，但代表行程结算币种的最小单位。旧记录无币种时按 CNY 解释，不迁移、不删除旧数据。
- 汇率方向统一为“1 原币 = N 结算币”，最多八位小数；用整数/十进制运算完成换算，再四舍五入到结算币最小单位，禁止浮点累加记账。
- 云端重新校验和计算换算值，不能信任客户端提交的结算金额。自动汇率引用服务端保存的报价，不允许客户端伪造自动来源。
- 保存后的快照不随行情变化。已完成结算仍使用现有历史锁定和调整账单逻辑。

## 接口与安全

- 汇率由云函数请求固定供应商地址，不在客户端保存密钥，不向供应商发送昵称、账单内容或行程标识。
- 按币种对和日期缓存。显示实际数据日期；不承诺金融交易可执行价或微信扣款价。
- 自动来源优先固定 ECB 数据，发布前核对供应商及上游条款和云端连通性。
- 本机演示模式保留手动/实付方式，不伪造自动报价。

## 验收

- 原人民币账单、行程、权限与结算回归不变。
- 均分和按份数的换算后分摊合计精确一致。
- 零小数币种、八位汇率、尾差、过小/超限/非法数值均覆盖。
- 自动报价超时/错误/币种日期不匹配时不能提交虚假的自动汇率。
- 编辑账单保留汇率快照，跨日期/币种更新不复用不匹配报价。
- 实际扣款金额优先，仍保留原币金额供核对。
- 双端账本显示同币种、同金额；最终真机验收独立于本地测试记录。

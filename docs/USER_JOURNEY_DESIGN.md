# 喵喵旅账：用户视角界面调整

2026-10-04

## 设计方案

保留复古猫咪旅行插画、奶油纸色与深绿主色；缩短装饰区域，让账目与操作先出现。使用现有云端身份与数据，不清空登录、草稿或账本。

主流程：首次完善微信头像昵称 → 我的行程 → 创建或匹配码加入 → 共享账本 → 记账 → 账单详情 → 结算 → 付款方确认已转账 → 收款方确认到账。

邀请是行程内随时可达的分支，不强制作为记账前置步骤。新增独立邀请页，集中放置微信分享、二维码和六位匹配码；保留创建者权限，不自动生成邀请或扩大访问权限。

## 各页调整

| 页面 | 用户要看见的重点 | 下一步 |
| --- | --- | --- |
| 登录/资料 | 当前微信身份、头像昵称用途、真实加载/失败状态 | 进入行程或恢复邀请 |
| 我的行程 | 进行中与待结算、自己的应收应付 | 创建行程 / 加入行程 |
| 创建行程 | 名称、结算币种、日期；手填成员与微信加入的区别 | 创建共享账本 |
| 共享账本 | 总消费、我垫付与应承担、最新账单 | 记账 / 结算 / 邀请旅伴 |
| 邀请旅伴（新增） | 行程名、邀请状态、分享/二维码/匹配码 | 好友在自己的微信中加入 |
| 加入行程 | 邀请人、行程、将加入的身份 | 确认加入；失效时返回首页 |
| 记一笔 | 金额与币种优先，谁付/谁分；一句话录入可展开 | 核对并保存 |
| 账单详情 | 原币、折算、付款人、分摊与修改记录 | 返回账本 / 编辑 |
| 同行伙伴 | 成员身份、本人头像、离线成员含义 | 邀请微信好友 / 管理成员 |
| 结算 | 我待付/待收、谁转给谁、双方确认进度 | 实际转账后确认，收款方核实到账 |

## 边界与验证

- 不伪造微信账号选择弹窗，不自动获取头像；头像由用户主动选择。
- 小程序不扣款、不跳转或代发微信转账；状态按钮只能记录确认，须二次确认。
- 不更改服务端金额、汇率、成员或付款权限，不执行真实转账。
- 页面测试覆盖身份展示、邀请只读加载、结算确认/取消/失败和返回路径；再检查开发工具渲染及页面入口。
- 不把本地模拟器验证称为双真实账号端到端测试。

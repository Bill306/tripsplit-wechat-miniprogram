# TripSplit MVP 测试计划

日期：2026-09-21

## 纯函数覆盖

```text
money
  ├─ 合法元金额 -> 整数分
  ├─ 0 / 负数 / 超上限 / 超两位小数 -> 拒绝
  └─ 分 -> 带千分位的展示金额

split
  ├─ 均分可整除
  ├─ 均分尾差按稳定顺序分配
  ├─ 按份数可整除
  ├─ 按份数尾差按稳定顺序分配
  └─ 空成员 / 非法份数 -> 拒绝

ledger
  ├─ 付款人参与 / 不参与
  ├─ 忽略软删除账单
  ├─ paid / owed / net 正确
  └─ 净额合计非 0 -> 拒绝结算

settlement
  ├─ 一借一贷
  ├─ 多借多贷
  ├─ 已平衡 -> 空转账
  └─ 每人执行转账后余额归零
```

## 开发者工具流程

- 创建行程 -> 添加 3 名离线成员 -> 进入详情。
- 记录全员均分、部分人参与、付款人不参与和按份数账单。
- 杀掉页面后重开，未提交草稿仍存在。
- 连续点击两次提交，只创建一笔账单。
- 网络错误时表单不清空，可重试。
- 结算列表所有转账执行后，成员余额全部归零。

## 真实多人 E2E

1. 账号 A 创建行程并生成邀请。
2. 账号 B 通过邀请加入，A/B 端成员一致。
3. A 与 B 各创建账单，双端刷新后账本和统计一致。
4. 模拟旧 revision 编辑，确认冲突不覆盖新值。
5. A 发起结算；付款方标记已支付，收款方确认已收款。
6. 所有转账完成后 Trip 为 `settled`。
7. 新增调整账单后 Trip 为 `needs_settlement`，历史结算仍只读。

## 失败模式验收

| 故障 | 自动测试 | 处理 | 用户可见 |
| --- | --- | --- | --- |
| 金额尾差 | 是 | 稳定排序分配 | 详情显示每人金额 |
| 网络超时后重试 | 是 | clientRequestId 去重 | 重试提示 |
| 并发编辑 | 是 | expectedRevision 冲突 | 需重新编辑 |
| 结算时账本变化 | 是 | revision 事务断言 | 刷新后重试 |
| 无权越权写入 | 是 | 云函数成员/角色校验 | 无权限提示 |
| 双重收款确认 | 是 | 单事务幂等收敛 | 显示最终状态 |
